# AGENTS.md

Инструкции для ИИ-агентов (Claude Code, Codex, Cursor, Copilot и др.), работающих с этим репозиторием.
Люди тоже могут читать: это краткое описание правил проекта.

## Проект

**MeshChat** — учебный mesh-мессенджер для Android (курс «Разработка мобильных приложений»).
Устройства обмениваются текстовыми сообщениями без интернета и серверов, пересылая пакеты через промежуточные узлы (multi-hop). Сообщения сквозно шифруются.

- Язык: **Kotlin** (только Kotlin, без Java в новом коде)
- IDE/сборка: Android Studio, Gradle Kotlin DSL, version catalog (`gradle/libs.versions.toml`)
- `minSdk` 28, `targetSdk` и `compileSdk` — актуальные стабильные
- Пакет: `io.github.vokrob.meshchat`

## Границы MVP

Входит: обнаружение соседей, обмен текстом, multi-hop (controlled flooding), локальная история, E2E-шифрование, store-and-forward, ACK.
**Не входит** (не добавлять без явной просьбы): файлы, группы, голос/видео, карта узлов, облачные сервисы, аккаунты, аналитика, реклама.

## Архитектура

Слои и направление зависимостей: `ui → domain → data`. Обратных зависимостей быть не должно.

```
app/                    # Application, MainActivity, навигация, Hilt-граф
core/
  common/               # qualifier'ы диспетчеров, общий DI
  model/                # общие модели (PeerId, MessageId, ...)
  mesh/                 # MeshTransport, MeshRouter, формат пакета, дедупликация
  crypto/               # ключи, подписи, шифрование (обёртка над Tink)
  database/             # Room: сущности, DAO, миграции
  ui/                   # тема Material 3, общие Compose-компоненты
feature/
  chat/                 # список чатов и экран переписки
  peers/                # обнаруженные устройства
  onboarding/           # разрешения, создание профиля и ключей
build-logic/            # convention-плагины (meshchat.android.library, meshchat.android.compose, ...)
```

Общие настройки Gradle (compileSdk/minSdk, Java 11, ktlint, detekt, Compose) живут в convention-плагинах `build-logic`; в `build.gradle.kts` модулей остаются только namespace и специфичные зависимости.

Правила:

- **UI:** Jetpack Compose + Material 3, Navigation Compose. Никакого XML-вёрстки и Fragment.
- **Паттерн:** MVVM с однонаправленным потоком данных. ViewModel отдаёт один `StateFlow<UiState>`, события UI приходят как `UiEvent`/методы ViewModel, одноразовые эффекты — через `Channel`/`SharedFlow`.
- **Domain:** чистый Kotlin, без зависимостей от `android.*`. Use case — один класс, одна операция (`operator fun invoke`).
- **Data:** репозитории скрывают Room и транспорт за интерфейсами из `domain`.
- **DI:** Hilt. Конструкторная инъекция, `@Binds` для интерфейсов. Никаких синглтонов-объектов с глобальным состоянием.
- **Асинхронность:** Coroutines + Flow. Диспетчеры внедряются (`@IoDispatcher` и т.п.), не хардкодятся. `GlobalScope` запрещён.
- **Транспорт:** всё, что связано с Nearby Connections, живёт только за интерфейсом `MeshTransport`. Роутер и домен ничего не знают о Nearby/BLE.

```kotlin
interface MeshTransport {
    val incoming: Flow<RawPacket>
    val peers: StateFlow<Set<PeerId>>
    suspend fun start()
    suspend fun stop()
    suspend fun send(to: PeerId, packet: ByteArray): Result<Unit>
}
```

Реализации: `NearbyTransport` (основная), `FakeTransport` (тесты и демо без железа).

## Mesh-протокол

- Пакет: `messageId` (UUID), `senderId`, `recipientId`, `ttl`, `timestamp`, `type` (`MESSAGE`/`ACK`), `payload`, `signature`.
- Сериализация: kotlinx.serialization (Protobuf). Формат версионируется полем `version`.
- Получив пакет: проверить подпись → дедупликация по `messageId` (LRU-кэш) → если адресат мы, расшифровать и сохранить, отправить ACK → иначе `ttl--` и переслать всем соседям, кроме отправителя, пока `ttl > 0`.
- Нет соседей → пакет остаётся в очереди Room и уходит при появлении узла.
- `ttl` по умолчанию ограничен константой в `core/mesh`, магические числа в коде запрещены.

## Безопасность (обязательные правила)

- **Не писать криптографию самостоятельно.** Только Google Tink (или libsodium). Никаких своих шифров, ручного XOR, самодельных KDF.
- Ключи: Ed25519 (подпись), X25519 (обмен ключами), AEAD для содержимого (ChaCha20-Poly1305 или AES-GCM). Приватные ключи защищены Android Keystore, не хранятся в открытом виде и не попадают в логи, бэкапы и Room.
- Подписывается каждый пакет; пакет с неверной подписью молча отбрасывается.
- Nonce никогда не переиспользуется.
- В логи не писать содержимое сообщений, ключи, полные идентификаторы. Использовать Timber, в release-сборке логирование отключено.
- `android:allowBackup="false"` (или явные правила, исключающие ключи и БД).
- Известные ограничения (метаданные «кому» видны ретрансляторам) документируются в README, а не скрываются.

## Разрешения и фон

- Android 12+: `BLUETOOTH_SCAN`, `BLUETOOTH_ADVERTISE`, `BLUETOOTH_CONNECT`; Android 13+: `NEARBY_WIFI_DEVICES`, `POST_NOTIFICATIONS`; до Android 12: `ACCESS_FINE_LOCATION` (с `maxSdkVersion`).
- Запрашивать разрешения с объяснением и обрабатывать отказ («не спрашивать снова») без падений.
- Работа узла в фоне — Foreground Service с типом `connectedDevice` и корректным уведомлением. Скан и advertising не должны работать вхолостую; останавливать при отсутствии необходимости.

## Тесты и качество

Перед завершением любой задачи агент **обязан** прогнать:

```bash
./gradlew ktlintCheck detekt
./gradlew testDebugUnitTest
./gradlew assembleDebug
```

- Unit-тесты обязательны для: `MeshRouter` (дедупликация, TTL, store-and-forward), `crypto`, use cases, мапперов.
- Room — инструментальные тесты или Robolectric; Compose — UI-тесты основных экранов.
- Тесты используют `FakeTransport`, а не реальный Nearby.
- Новая логика без тестов не принимается; падающие тесты не отключать и не удалять ради «зелёной» сборки.

## Стиль кода

- Официальный Kotlin style guide, ktlint, detekt (конфиг в репозитории).
- Публичные API `core:*` документируются KDoc.
- Предпочитать `val`, неизменяемые data-классы, sealed-иерархии для состояний и ошибок.
- Ошибки: `Result`/sealed-типы в domain, не глотать исключения молча, `CancellationException` не перехватывать.
- Строки только в `strings.xml` (ru и en), цвета/типографика — из темы, не хардкод.
- Compose: composable-функции без побочных эффектов, `remember`/`LaunchedEffect` по назначению, `@Preview` для ключевых экранов, состояние поднимается вверх (state hoisting).

## Зависимости

- Версии только через `libs.versions.toml`. Не добавлять библиотеку без необходимости; если добавляется, объяснить зачем.
- Не использовать устаревшие API (AsyncTask, LiveData для нового кода, kapt там, где есть KSP).

## Git и процесс

- Небольшие осмысленные коммиты, формат Conventional Commits: `feat(mesh): add TTL check`, `fix(chat): ...`, `test(crypto): ...`.
- Одна задача — одна ветка (`feature/...`, `fix/...`).
- Не коммитить: `local.properties`, ключи подписи, keystore, `.idea/` (кроме общих настроек), артефакты сборки.
- Перед крупными изменениями структуры модулей — сначала короткий план, затем реализация.

## Чего агенту делать нельзя

- Менять публичные интерфейсы `MeshTransport`, формат пакета или схему БД без явной просьбы и миграции.
- Добавлять сетевые запросы в интернет, сторонние SDK трекинга, облачные бэкенды.
- Отключать проверки безопасности, подпись, шифрование «для упрощения отладки».
- Генерировать код «на будущее», выходящий за запрошенную задачу.
- Придумывать API, в существовании которых нет уверенности: сверяться с официальной документацией Android и Nearby Connections.

## Демо-сценарий (для проверки результата)

Три физических устройства: A — B — C, где A и C не видят друг друга напрямую. Сообщение от A доходит до C через B, приходит ACK, при отсутствии B сообщение ждёт в очереди и доставляется после его появления. Эмуляторы для проверки реального транспорта не подходят.
